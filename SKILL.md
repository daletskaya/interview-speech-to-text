# Расшифровка интервью

Задача скилла — превратить запись созвона в читаемый диалог с тайм-кодами,
по которому можно искать моменты в видео.

Главная мысль: **распознавание — это черновик, а не результат.** Модель
срывается на русском предсказуемыми способами, разметка говорящих ошибается
на наложениях речи, а названия брендов превращаются в кашу. Скилл устроен так,
чтобы каждый из этих сбоев был найден и показан, а не прошёл незамеченным.

Скрипты лежат в `scripts/`. Перед первым запуском прочитай
[`references/okruzhenie.md`](references/okruzhenie.md): что поставить, каким
питоном запускать и что делать, если ffmpeg или модель капризничают.

Человека установкой не нагружай. Он скачал скилл и попросил расшифровку —
всё остальное твоя работа. Спрашивай только то, чего без него не решить.

## 0. Проверь, нет ли новой версии

```
scripts/update.sh check
```

Есть новая версия — одной строкой скажи, что изменилось, и спроси,
обновить ли сейчас. Согласился — `scripts/update.sh apply`, потом
перечитай этот файл: инструкция могла поменяться. Отказался, GitHub
не ответил или скилл поставлен архивом — не настаивай и переходи
к расшифровке. Посреди расшифровки не обновляй: скрипты поменяются
под руками.

Если человек просит обновить скилл отдельно от расшифровки — сразу
`scripts/update.sh apply`. Скрипт сам скажет, если обновиться нельзя
и что для этого сделать.

## 1. Разберись, что на входе

Выясни порядок записей и нет ли между ними дыр. У многих платформ время старта
стоит прямо в имени файла, но проверять нужно по длительностям: конец одной
записи должен стыковаться с началом следующей.

```
ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 ФАЙЛ
```

Если между записями разрыв — скажи об этом сразу и назови, сколько минут
разговора не записано. Склейка это не починит, а человек должен знать.

Короткие куски в начале (секунды) — обычно пустая комната до начала встречи.
Проверь уровень звука, прежде чем тащить их в склейку:

```
ffmpeg -t 30 -i ФАЙЛ -af volumedetect -f null - 2>&1 | grep mean_volume
```

Ниже −45 dB — это тишина.

Посмотри, нет ли вопросов из гайда: файл `вопросы.md` или `questions.md`
рядом с записью, файл в чате, вопросы прямо в сообщении или ссылка
на страницу с ними — например, на опросник в Конфлюенсе. Ссылку прочитай
через коннектор; если он не подключён, попроси вставить вопросы текстом.
Если на странице вопросы разделены на обязательные и остальные, сохрани
это разделение в отчёте. Если есть —
после расшифровки разложишь по ним ответы в отчёте (шаг 8). Заготовка
[`questions.md`](questions.md) в папке скилла пустая; вопросы оттуда бери,
только если под заголовком «Вопросы» что-то написано.

## 2. Подготовь файлы

```
scripts/prepare.sh ВЫХОДНАЯ_ПАПКА файл1 файл2 ...
```

Склеивает куски без пережатия, извлекает `audio16k.wav` и печатает путь
к записи, с которой работать дальше. Файлы перечисляй в хронологическом
порядке. Дальше всё идёт по `audio16k.wav`; видео понадобится, только если
голоса не разделятся (шаг 4) и для сверки в конце (шаг 7).

Видео по умолчанию не перекодируется: для расшифровки это не нужно, а стоит
минут. Ключ `--mp4` добавляй, только если человек просил именно mp4.

`audio16k.wav` не удаляй и оставь рядом с видео. Если видео потом обрежут,
только по нему можно будет измерить, на сколько уехали тайм-коды.

## 3. Распознай речь

```
scripts/transcribe.py audio16k.wav asr.json --words
```

Ключ `--words` добавляет тайм-коды слов: по ним на следующем шаге
определяются говорящие. Распознавание с ним идёт примерно вдвое дольше
(28 минут записи — три с половиной минуты вместо двух), зато голоса
различаются точнее. Если говорящих размечаешь по картинке, ключ не нужен.

Скрипт сам выбирает движок. На маках с процессором Apple это `mlx`: полчаса
записи за пару минут. Если он пишет, что считает на процессоре, значит,
не установлен `mlx-whisper` — поставь его по `references/okruzhenie.md`,
разница в двадцать раз.

Скрипт сам находит и перераспознаёт места, где модель сорвалась, — это не
опция, а основная его работа. Смотри, сколько участков он чинил: если много,
значит, запись тяжёлая, и вычитывать её надо тщательнее.

### Словарь

Словарь ищется сам: `глоссарий.md` или `glossary.md` рядом с записью, потом
в папках выше неё (так один словарь в общей папке интервью работает для всех
разговоров внутри), потом [`glossary.md`](glossary.md) в папке скилла.
Ближайший к записи главнее. Какой словарь взят, скрипт печатает — назови его
в ответе. В нём три раздела, и читают их разные участники.

Свой словарь не кладут в папку скилла: правка файла скилла помешает
обновлению. Его место — папка с интервью.

**Термины** уходят в подсказку модели перед распознаванием — она охотнее
узнаёт подсказанные слова в потоке речи. Держи список коротким, полтора
десятка слов. Длинная подсказка даёт обратный эффект: модель начинает
слышать подсказанное там, где его нет, — в паузах, в кашле, в чужой фразе.

**Замены** применяются к готовому тексту: с начала слова, без учёта регистра,
окончание свободно. Годятся только для однозначного. Замена вслепую опаснее
опечатки: похожее слово может оказаться обычным словом из речи.

**Бренды** не попадают ни в распознавание, ни в замены. Это список для тебя:
с чем сверить искажённое название, прежде чем поставить `(нрзбр)`.

Термины и замены читаются только из блоков кода — всё, что вне блоков,
скрипт не видит. Бренды читаешь ты, поэтому там обычный текст.

Если человек просит завести словарь — скопируй заготовку
[`glossary.md`](glossary.md) в `глоссарий.md` в общей папке его интервью
(не знаешь, какая общая, — спроси) и разложи его слова по разделам. Если
просит добавить слова — найди словарь, которым пользуется ближайшая запись,
и допиши туда. Объяснять ему формат не нужно.

## 4. Раздели говорящих

Работаем со звуком, видео по умолчанию не трогаем: так быстрее, а голос
на пробной записи размечал точнее картинки. По порядку:

```
scripts/audio_check.py ЗАПИСЬ
```

**Несколько аудиодорожек** — лучший случай: по одной на участника. Готового
скрипта под него нет, потому что встречается редко. Вынь каждую дорожку
(`ffmpeg -i ЗАПИСЬ -map 0:a:N -ac 1 -ar 16000 дорожка_N.wav`), распознай
по отдельности и слей сегменты по времени: говорящий — тот, чья дорожка.

**Одна дорожка** — так отдаёт запись большинства платформ. Тогда по голосу:

```
scripts/voices.py audio16k.wav asr.json speakers.csv --speakers 2
```

Число участников назови сам — по записи или со слов человека. Скрипт делит
фразы на столько голосов и для каждого печатает самые длинные фразы. По ним
и сопоставляй номера с именами: интервьюер спрашивает и ведёт по сценарию,
респондент рассказывает. Если по фразам не ясно, а видео есть — вырежи кадр
на секунде одной из них и прочитай подпись под говорящим.

Скрипт печатает и **различимость голосов**. Мужской и женский голос
разводятся уверенно (на пробной записи — 5,8). Если различимость ниже 3,
голоса похожи и разметке верить нельзя — переходи к картинке. Порог
подобран по одной записи, так что и выше трёх смотри, сходится ли разметка
со смыслом. Фразы под сомнением скрипт перечисляет отдельно: при вычитке
проверь их первыми.

**Голоса похожи или участников больше двух** — тогда ищем подсветку
активного участника в кадре. Картинка опаздывает за речью на секунду-полторы,
поэтому короткие реплики она путает чаще голоса.

```
scripts/speakers.py calibrate ЗАПИСЬ
scripts/speakers.py detect ЗАПИСЬ speakers.csv --color RRGGBB
```

Цвет и форма подсветки у каждой платформы свои, поэтому `calibrate` ищет её
в конкретной записи, а не знает заранее. **Проверь кандидата глазами**, прежде
чем строить по нему разметку: вырежи кадр на секунде, которую он назвал, и
посмотри, что подсвечен ровно один участник.

```
ffmpeg -ss СЕКУНДА -i ЗАПИСЬ -frames:v 1 -y кадр.png
```

`detect` сам находит плитки по парам вертикальных линий и печатает их
список с номерами. Участников может быть сколько угодно: интервьюер
с респондентом, двое интервьюеров, фокус-группа.

Для каждой плитки `detect` называет секунду, где она подсвечена одна. Вырежи
кадр на этой секунде и прочитай подпись под подсвеченной плиткой — так номера
сопоставляются с именами. По порядку номеров не угадывай. Плиток может оказаться больше, чем людей: если
в записи включали демонстрацию экрана, раскладка менялась и один человек
занимал разные места — тогда у него будет несколько номеров.

**Подсветки нет** — бывает. Тогда собирай без `--speakers` и расставляй
реплики по смыслу: интервьюер спрашивает, респондент рассказывает. Обязательно
скажи в ответе, что разметка сделана по смыслу, а не по данным.

## 5. Собери черновик

```
scripts/build.py asr.json черновик.md --speakers speakers.csv \
                 --names "0=Имя,1=Имя"
```

Если человек дал код респондента («гостя подписывай Г-03»), подписывай
им: `--names "0=Интервьюер,1=Г-03"`. Имя респондента тогда не пишется нигде —
ни в расшифровке, ни в шапке, ни в отчёте, ни в названии страницы. Если
имя прозвучало в самом разговоре, замени его в тексте на код.

Номера — те, что напечатал `voices.py` или `detect`. Если по картинке один
человек занимал несколько плиток, перечисли их с одним именем:
`--names "0=Интервьюер,2=Интервьюер,1=Гость"`.

Скрипт скажет, сколько каждый говорил и сколько времени говорили
одновременно: вот там разметка и ненадёжна.

## 6. Вычитай

Самый важный шаг, и единственный, который нельзя доверить скрипту.
Прочитай черновик целиком — да, все полчаса разговора.

**Правь черновик, а не пиши текст заново.** Скопируй `черновик.md`
в `расшифровка.md`, замени шапку и дальше меняй только то, что требует
правки: перепутанного говорящего, сорванное распознавание, паразиты.
Набирать заново полчаса разговора — самое долгое, что есть в этом скилле,
а правильные фразы от перепечатки лучше не становятся. Если реплику надо
отдать другому, разрежь её на месте и поставь тайм-код из черновика
(`asr.json` подскажет секунду, где началась фраза).

**Говорящие.** Ищи реплики, попавшие не тому: вопрос интервьюера внутри
ответа респондента, «супер, поняла» в конце чужого монолога. Когда говорят
разом, подсветка горит у нескольких, и там скрипт ошибается.

**Слова-паразиты.** Убирай «ну», «вот», «как бы», «там», «собственно»
и повторы-заикания. Оставляй то, что несёт смысл: «наверное», «мне кажется»,
«честно говоря» — это степень уверенности респондента, без неё ответ меняется.

**Неразборчивое помечай `(нрзбр)`, а не угадывай.** Особенно названия блюд,
брендов и числа. Угаданное слово в расшифровке выглядит ровно так же, как
расслышанное, и проверить его потом никто не сможет.

Прежде чем ставить `(нрзбр)` на искажённое название, сверься с разделом
«Бренды» в [`glossary.md`](glossary.md): респонденты постоянно поминают
конкурентов, и каша вроде «вкус.вилл» часто опознаётся с одного взгляда.
Но если совпадение натянутое — всё равно `(нрзбр)`.

Старое название сервиса не исправляй на новое. Если гость сказал «Деливери
Клаб» или «КФС», так и оставь: это его слова, а не ошибка распознавания.
Как люди называют сервисы — само по себе находка исследования.

**Очевидные ошибки распознавания правь молча**, но перечисли их в ответе:
перевранное название бренда — это ошибка, а подстановка слова по смыслу —
уже твоя догадка. Догадки назови отдельно, с тайм-кодами, чтобы их проверили.

## 7. Проверь и отдай

Открой видео на тайм-коде из середины расшифровки и сверь, что звучит там
то же, что написано. Проверять по началу бессмысленно: сдвиг накапливается.

Собери список неразборчивых мест и отдай его вместе с расшифровкой:

```
scripts/unclear.py расшифровка.md asr.json
```

Скрипт для каждого `(нрзбр)` печатает тайм-код, фразу вокруг и то, что
на этом месте услышал распознаватель. Последнее и есть главное: «кура-мису»
ничего не значит в тексте, но человек, который вёл интервью, по такому
звучанию вспоминает название блюда. Список без этой колонки
бесполезен — «тут неразборчиво» человек увидит и сам.

Если тайм-коды уже сдвигали под обрезанное видео, передай `--offset`
с тем же числом, что передавалось в `shift.py`.

Положи расшифровку рядом с видео. В ответе скажи:

- где лежит и сколько длится запись;
- список неразборчивых мест с тайм-кодами и тем, как они прозвучали;
- что подставлено по смыслу — отдельно от того, что расслышано;
- насколько надёжна разметка говорящих и где именно она шаткая.

## 8. Собери отчёт

Отчёт делай, если человек дал вопросы, попросил отчёт или попросил выложить
интервью в Конфлюенс. Иначе шага нет: хватит расшифровки.

Работай по готовой `расшифровка.md`, а не по черновику: цитаты должны
совпадать с текстом, который человек будет читать. Порядок:

1. Прочитай расшифровку целиком и собери черновик отчёта. Человеку его
   пока не показывай.
2. Задай вопросы ведущему (ниже) и дождись ответа.
3. Допиши отчёт по ответам, проверь цитаты и отдай.

Результат — `отчёт.md` рядом с расшифровкой. Разделы — в таком порядке:

```
# Интервью: Гость, 12 марта

Запись 41:05. Интервьюер — Анна. Расшифровка — в `расшифровка.md`.

## О респонденте

- Как часто заказывает: раз-два в неделю — [01:40] «Ну, пару раз в неделю точно»
- Где ещё заказывает: в двух сервисах доставки — [02:15] «Ещё в двух, смотря что хочется»

## Хайлайты

- Выбирает по скорости доставки, а не по цене.
  [03:12] «Главное — чтобы привезли за час, остальное потом»

## Ответы по вопросам

### Как вы выбираете, где заказать?

Смотрит на скорость доставки; отзывы читает, только если сервис незнакомый.

- [03:12] «Главное — чтобы привезли за час, остальное потом»
- [17:40] «Отзывы смотрю, если первый раз там заказываю»

## Выводы ведущего

- Главное: гость не видит, сколько ждать, и уходит туда, где это видно.
- Удивило: отзывы почти не читает, хотя мы ждали обратного.
```

**О респонденте** — факты, которые он сам назвал: как часто заказывает,
чем пользуется, с кем, на каком устройстве, давно ли знает сервис. Каждый
факт — с цитатой. Чего не прозвучало, не пиши и не выводи из косвенного:
«наверное, студент» — догадка, а не данные.

**Хайлайты** — пять–десять самых важных мыслей интервью: проблемы, на
которые респондент наткнулся, неожиданные привычки, сильные реакции на
прототип. Каждый — одна фраза своими словами и цитата под ней. Сюда же
то важное, что не легло ни в один вопрос: неожиданное часто ценнее
ожидаемого.

**Ответы по вопросам** — только если вопросы есть. Порядок и формулировки —
как у человека, разделы гайда сохраняй. Под каждым вопросом — одно-три
предложения, что ответил респондент, и цитаты.

**Ищи ответ по всему разговору.** Респонденты отвечают раньше, чем их
спросили, возвращаются к теме через десять минут, а интервьюер
переформулирует вопрос или пропускает. Ответ из другой части интервью —
всё равно ответ на этот вопрос.

**Цитаты — дословно.** Слово в слово из расшифровки, одна цитата — из одной
реплики. Пропуск внутри помечай многоточием. Не поправляй речь и не склеивай
куски из разных мест: подправленная цитата выглядит как настоящая,
и ошибку уже никто не найдёт. `(нрзбр)` оставляй как есть. Тайм-код —
реплики, из которой цитата; если реплика длинная, можно точнее, по `asr.json`.

**Цитируй респондента.** Если он только согласился с вариантом интервьюера
(«— Неудобно было? — Да»), так и напиши: ответ на наводящий вопрос весит
меньше, чем сказанное самим человеком.

**Нет ответа — так и пиши.** «Не обсуждали», если вопрос не прозвучал;
«Ответа по существу нет», если прозвучал, а респондент ушёл в сторону.
Не натягивай на вопрос соседнюю тему — пустой ответ честнее.

**Нет в расшифровке — нет в отчёте.** В разделах до «Выводов ведущего» —
только то, что сказал респондент. Догадки («наверное, торопился»), свои
и чужие, туда не идут. Слова ведущего не выдавай за слова респондента.

**Выводы ведущего** — отдельный последний раздел, только из ответов ведущего
на твои вопросы и его заметок, если он их приложил. Так видно, где
сказанное человеком, а где понимание того, кто был на интервью.

### Вопросы ведущему

Часть того, что понял ведущий, в расшифровке нет: что человек показывал
на экране, где замялся, что было в неразборчивом месте. Поэтому, прочитав
расшифровку, задай ведущему 3–5 коротких вопросов **одним сообщением**.
Вопросы конкретные — с цитатой или тайм-кодом, где можно — с вариантами
ответа.

Всегда:
- три главные мысли после разговора (если ведущий не приложил заметку);
- что удивило или не совпало с ожиданиями.

По ситуации, одно-три:
- чего не хватает для шапки: дата записи, кто вёл, код респондента. Дату
  бери из имени файла или из слов в разговоре; дата файла на диске — это
  день, когда его скачали или скопировали, а не день интервью. Не нашлось —
  спроси, а не ответили — пиши «дата не указана»;
- неразборчивое место, которое попадает в цитату: что там было;
- двусмысленный ответ: цитата и два прочтения на выбор;
- что было видно, но не слышно: что человек показывал, где замялся;
- какая из найденных проблем главная, по ощущению ведущего.

Что делать с ответами:
- ответы — в «Выводы ведущего», в остальные разделы их не подмешивай;
- ведущий закрыл неразборчивое место — замени `(нрзбр)` и в расшифровке,
  и в цитате на `слово [со слов ведущего]`, одинаково в обоих файлах:
  тогда проверка цитат сойдётся, а читатель видит, откуда слово;
- ведущий не ответил или не знает — пиши «ведущий не уточнил»
  и не переспрашивай.

Расшифровку просит не сам ведущий, а коллега, или ведущий сказал «без
вопросов» — не спрашивай, а в «Выводах ведущего» напиши «ведущего
не опрашивали».

Проверь цитаты:

```
scripts/quotes.py отчёт.md расшифровка.md --speaker Имя_респондента
```

Скрипт находит цитаты, которых нет в реплике под их тайм-кодом, и цитаты
из чужих реплик. Исправь всё, что он нашёл, и запусти снова. Чужая реплика
допустима, только если ты цитируешь вопрос намеренно, — тогда это должно
быть понятно из текста.

В ответе человеку скажи, на какие вопросы ответа не нашлось.

## 9. Выложи в Конфлюенс

Только если человек попросил — в запросе или в ответ на твой вопрос. Сам
не предлагай выкладывать каждый раз: это публикация, а не сохранение.

Нужен подключённый коннектор Atlassian (Конфлюенс). Если его инструментов
в сессии нет — скажи, что Конфлюенс надо подключить в настройках
коннекторов, и отдай файлы локально. Не выкладывай через API руками
и не проси у человека токен.

**Куда.** Пространство и родительскую страницу узнай у человека и запиши
в `confluence.md` рядом с записями:

```
Пространство: RESEARCH
Родительская страница: https://…/wiki/spaces/RESEARCH/pages/123456
Название: дата · тип · код респондента
Метки: research, interview
```

«Название» и «Метки» — по желанию команды. Есть «Название» — собери
заголовок по нему, нет — бери заголовок отчёта. Есть «Метки» — поставь их
на страницу (у коннектора Atlassian — `addLabelsToConfluenceContent`).
Если в файле написано что-то сверх этого — например, в какой статус ставить
страницу, — следуй и этому.

Ищи `confluence.md` так же, как словарь: рядом с записью, потом в папках
выше. В следующий раз файл подхватится сам, и спрашивать не придётся. Перед
публикацией всё равно назови, куда и под каким названием создаёшь страницу.

**Что.** Страница — это `отчёт.md` (шаг 8), название — его заголовок.
Меняется одна строка в шапке: «Расшифровка — в `расшифровка.md`» становится
«Расшифровка — во вложении». Расшифровку на страницу не переписывай: полчаса
диалога никто не читает в Конфлюенсе, а набор такого текста — самое долгое,
что есть в скилле. Расшифровка идёт вложением:

- если у коннектора есть инструмент для вложений — прикрепи
  `расшифровка.md` к странице сам. У коннектора Atlassian это операция
  `createConfluenceAttachment` (найди её через `discover`): она возвращает
  команду загрузки, которую ты запускаешь у себя в терминале. Файл уходит
  прямо в Конфлюенс, текст через тебя второй раз не проходит;
- если нет, а у тебя есть браузер, который умеет загружать файлы
  (например, Claude in Chrome), — открой созданную страницу в браузере
  человека, где он уже вошёл в Конфлюенс, и загрузи файл через вложения
  страницы. Входить в Конфлюенс за человека нельзя: если браузер просит
  вход, попроси войти его самого;
- если и браузера нет — попроси человека перетащить файл на страницу
  и назови путь к нему.

Неразборчивые места на страницу не идут: они для того, кто вёл интервью,
и остаются в `неразборчивое.md`.

**Личные данные.** Перед публикацией просмотри отчёт и расшифровку
на телефоны, адреса и почту респондента. Если они есть — назови места
и спроси, заменить ли их на `[телефон]`, `[адрес]`. Страницу и вложение
увидят все, у кого есть доступ к пространству, а не только те, кто был
на интервью.

**Обновления.** Ссылку на созданную страницу запиши
в `confluence-страница.md` рядом с расшифровкой. Если потом отчёт правили —
обновляй эту страницу, новую не заводи.

В ответе дай ссылку на страницу.

## Если видео обрезали после расшифровки

Тайм-коды разъедутся. Не пересчитывай их на глаз и не верь секундам,
названным по памяти, — измерь:

```
scripts/align.py ОБРЕЗАННОЕ_ВИДЕО исходный_audio16k.wav
scripts/shift.py расшифровка.md СМЕЩЕНИЕ
```

`align.py` находит, где звук обрезанного файла начинается в исходном.
Если пик корреляции ниже пяти — измерению верить нельзя, разбирайся,
тот ли это файл. Сходится ли смещение с разницей длительностей —
хорошая дополнительная проверка.
